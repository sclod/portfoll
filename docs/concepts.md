# Три концепции

> Заметка: бриф по визуалу в эту сессию не попал, пришли только контентный и автономный.
> Концепция A восстановлена по её названию «внутренняя операционная панель» и по контенту, без исходного текста брифа.

Общие ограничения для всех трёх: системные шрифты (без загрузки веб-шрифтов, ради скорости),
порядок блоков из брифа, ноль выдуманных цифр.

---

## A. Внутренняя операционная панель

**Идея.** Сайт выглядит как админка внутренней системы: слева сайдбар-навигация, сверху строка
состояния, проекты как строки таблицы со статусами, по клику раскрывается деталь. Так посетитель
сразу видит интерфейс, который этот человек строит каждый день.

**Палитра:** `#0f1216` фон · `#171b21` панель · `#262c34` линии · `#dfe3e8` текст · `#5b9cf5` акцент · `#46c37b` статус «работает»

**Шрифты:** system-ui для интерфейса, ui-monospace для идентификаторов, дат и колонок.

```
┌──────────┬──────────────────────────────────────────────────────┐
│ ▣ Д.Р.   │  Огляд                                  [Telegram ↗] │
│──────────│──────────────────────────────────────────────────────│
│ Огляд    │  Данііл Репецький · Strong Junior · Київ             │
│ Проєкти  │  ┌────────────┬────────────┬────────────┐            │
│ Стек     │  │ Проєкти  3 │ У проді  1 │ Ботів  2+  │  ← KPI     │
│ Про мене │  └────────────┴────────────┴────────────┘            │
│          │  Назва                  Статус     Період   Стек     │
│          │  CRM юр. практики       ● прод     2023—    PG, TG   │
│          │  VehicleFlow Demo       ○ демо     —        Next     │
│          │  Telegram-боти          ·          23—24    aiogram  │
└──────────┴──────────────────────────────────────────────────────┘
```

**Отличие от увиденного.** Не карточки и не hero, а интерфейс. Но «дашборд-портфолио» тоже уже
встречается, а KPI-плашки сразу толкают к цифрам, которых в брифе нет («Ботів 2+» — уже выдумка).
На мобильном сайдбар и таблица разваливаются: в итоге получится адаптивная админка, а не страница для чтения.

## B. Журнал подій (audit log)

**Идея.** Страница как журнал действий: каждая запись — строка с датой, типом события и описанием,
как в журнале, который он сам делал для CRM. Проекты, обучение и стек становятся событиями во
времени, читатель листает историю человека как лог.

**Палитра:** `#0d0f12` фон · `#14171c` строка-зебра · `#2a2f37` линии · `#d6dae0` текст · `#e0a84f` акцент-тип события · `#7fb6ff` ссылки

**Шрифты:** ui-monospace для всего «служебного» (время, тип, id), system-ui для текста сообщений.

```
 ЖУРНАЛ · Данііл Репецький                          фільтр: [усі ▾]
 ─────────────────────────────────────────────────────────────────
 2023—  DEPLOY   CRM для юридичної практики · у продакшені дотепер
               ▸ ролі ADMIN / OPERATOR / VIEWER, журнал дій, Telegram
 2023—24 BUILD   Telegram-боти для бізнесу
               ▸ рієлторський каталог з фільтрами · боти-магазини
 ????    BUILD   VehicleFlow Demo                       ← даты нет
 2021    LEARN   Комп'ютерна академія ШАГ — курс Python
 ─────────────────────────────────────────────────────────────────
```

**Отличие от увиденного.** Таймлайн в портфолио бывает, но в виде «карьерной лесенки» с кружками.
Здесь — сухой системный журнал, это его реальный предмет работы. Минусы: ломает порядок блоков из
брифа (проекты → стек → сильные стороны), у VehicleFlow нет даты (придётся либо выдумать, либо дыра),
а стек и сильные стороны в журнал не ложатся вовсе.

## C. Картка запису

**Идея.** Страница — это одна запись во внутренней системе, обычный экран «карточка» из CRM: поля
«название — значение», статус, связанные записи и внизу история изменений. Проекты — дочерние
карточки систем с полями «Призначення / Функції / Стан / Код / Стек»: так описывают систему в
реестре, а не продают в портфолио.

**Палитра:**
- тёмная: `#111316` фон · `#181b1f` карточка · `#2c3137` линии · `#e4e6e9` текст · `#9ba3ad` подписи · `#8ab4ff` акцент
- статусы (единственный цвет со смыслом): `#5fcf8a` у продакшені · `#e2b45c` демо
- светлая: `#f3f3f0` · `#ffffff` · `#d6d7d2` · `#17191c` · `#545b64` · `#1d5fbf`

**Шрифты:** system-ui для значений и текста, ui-monospace для меток полей, дат и стека.

```
 Данііл Репецький                   Проєкти Стек Про мене   [Тема: темна]
 ════════════════════════════════════════════════════════════════════════
 ЗАПИС / РОЗРОБНИК
 Данііл Репецький                                    [ Написати → TG ]
 Роблю внутрішні системи для бізнесу — CRM, телеграм-боти, інтеграції…
 ────────────────────────────────────────────────────────────────────────
 РІВЕНЬ   Strong Junior        МІСТО    Київ
 БАЗА     Python, SQL          ЗВ'ЯЗОК  Telegram @D0SIDE0

 ПРОЄКТИ · 3 записи
 ┌ CRM для юридичної практики ─────────────────────── ● У продакшені ┐
 │ ПЕРІОД       2023 — дотепер                                        │
 │ ПРИЗНАЧЕННЯ  Внутрішня система, зроблена з нуля, підтримую сам     │
 │ ФУНКЦІЇ      — Картки клієнтів, документи, задачі, нагадування…    │
 │              — Рольова модель ADMIN / OPERATOR / VIEWER …          │
 │ КОД          Закритий — тільки опис                                │
 │ СТЕК         PostgreSQL · Telegram Bot API · Linux · Nginx · PM2   │
 └────────────────────────────────────────────────────────────────────┘
```

**Отличие от увиденного.** Нет hero-слогана, нет сетки скриншотов и «таблеток», нет процентов.
Структура «поле — значение» — это не стилизация под что-то, а формат, в котором он работает каждый
день. И он идеально подходит под закрытый код: поле «Код: закритий — лише опис» стоит рядом с
детальным списком функций, ровно как советуют источники из research.md.

## Выбор: C — «Картка запису»

**Критерий:** меньше всего похоже на то, что есть у всех, и честно отражает человека, который строит
внутренние системы, а не рисует интерфейсы.

- **A проигрывает по первой половине.** Дашборд-портфолио — уже узнаваемый жанр, а его KPI-плашки
  требуют цифр, которых у нас нет. Это «рисование интерфейса» вместо описания систем.
- **B честнее A, но ломает бриф.** Не держит порядок блоков, а у VehicleFlow нет даты: журнал без даты
  — это дыра, а дата — это выдумка.
- **C** — экран записи, самая будничная и поэтому самая правдивая часть любой внутренней системы.
  Она держит порядок блоков из брифа, все поля заполняются дословно из контента, а пустое поле
  просто не выводится. Из B забираю одно: **журнал** внизу, но только из фактов с датами
  (2021 ШАГ, 2023 CRM, 2023–2024 боти). VehicleFlow в журнал не попадает, раз даты нет.

### Проверка на себя: что я сделал бы для любого портфолио — и что поменял

| Было бы «как у всех»                                     | Что сделал вместо этого                                                                 |
|----------------------------------------------------------|----------------------------------------------------------------------------------------|
| Огромное имя на полэкрана + слоган + кнопка              | Заголовок записи нормального размера, под ним **поля** (рівень, місто, база, зв'язок). Кнопка «Написати» одна, как требует бриф |
| Мятный/зелёный акцент «как в терминале» (так было в первой версии) | Нейтральный графит + спокойный синий только для ссылок и фокуса. Зелёный и янтарный — **только как статусы** «у продакшені» / «демо» |
| Теги-«таблетки» под проектом                             | Поле «Стек» обычной строкой в моноширинном, через « · », как значение в карточке        |
| Карточки 2×2 с цветной полоской для сильных сторон       | Нумерованный список «поле — значение», без декоративной рамки                           |
| Три карточки стека с точками-индикаторами                | Таблица «рівень → технології»: три строки, как матрица ролей; без шкал и точек        |
| Иконки солнца/луны на переключателе темы                 | Текстовая настройка «Тема: темна / світла», как поле в настройках системы               |
| Блок «Задача / Результат» с придуманными связками         | Поля заполняются только дословным контентом; где факта нет (что было сложным, задача у ботов), поле не выводится |
| Отдельная плашка «Освіта»                                 | Журнал изменений из датированных фактов, внизу записи, как «Історія змін» в его CRM    |

## Итерация 2 — «вау»-версия по запросу

После просмотра заказчик сказал, что «Картка запису» выглядит сыро, и попросил 3D-фигуры, живой фон
и разные цвета/шрифты, чтобы подсвечивать важное «как у кодера». Структура и контент остались те же,
поменялась подача:

- **3D без библиотек.** Куб с гранями CRM / BOT / SQL / API / LOGS / LINUX (это его реальные направления),
  дротяной куб вокруг, две орбиты, сетка-пол в первом экране; стек — три изометрических плиты
  «фундамент → надбудова»; в контактах — дротяная сфера. Всё на `transform-style: preserve-3d`.
- **Цвет = смысл, как подсветка в редакторе.** Технологии — синим моноширинным, роли ADMIN/OPERATOR/VIEWER —
  бирюзовым, даты — оранжевым, статусы «у продакшені / в проді» — зелёным, служебные подписи — цветом
  комментария `//`. Расставляет фильтр `hl` в `build.py` автоматически по списку технологий из контента,
  руками ничего размечать не надо.
- **Шрифты.** Unbounded — заголовки, Manrope — текст, JetBrains Mono — код и подписи. Лежат локально
  в `fonts/` (~160 КБ, лицензия OFL), без запросов к Google.
- **Карточка `about.py`.** Факты из брифа в виде словаря Python — Python его основной язык.
- **Отступление от итерации 1.** Там я отказался от «кодерской» стилизации как от клише. Здесь она
  вернулась по прямой просьбе, но в одном месте (about.py) и как подсветка смысла, а не как фейковый терминал.
- JS по-прежнему только переключатель темы. Появление секций при прокрутке — CSS scroll-driven animations;
  где не поддерживается, всё просто видно сразу. `prefers-reduced-motion` выключает всю анимацию.
